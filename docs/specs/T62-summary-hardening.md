# T62：週報改寫的審查修正

接 T48（`docs/specs/T48-digest-ai-summary.md`）。joplin-op 2026-11-21 審查 T48 的第 1、2、3、6、7 項。第 4、5 項機率低，另列 T63。

## 1. 05:51 找不到週報 → 重試，發布日找不到要報錯

目前：`digest_summary.py` 05:51 找不到今天的摘要就印「今天沒有摘要筆記」並 exit 0。05:50 的發布 Job 只要晚 30 秒（晚啟動、重試、來源逾時），06:00 就會送出完整列表，log 也看不出異常。

期望：
- 新增環境變數 `NEWS_PUBLISH_WEEKDAY`（主機的 `~/.config/news-summary.env`，跟 K8s ConfigMap 同值）。留空 = 每天都是發布日。
- **不是發布日**：找不到就 exit 0，不重試（跟現在一樣）。
- **發布日**：找不到就每 30 秒重找一次，直到 05:58；05:58 還找不到就印錯誤並 exit 1。
- 呼叫 `claude -p` 的逾時改成 `min(420 秒, 距離 05:59:30 的秒數)`；剩不到 60 秒就不呼叫，印錯誤並 exit 1（筆記不改，06:00 照舊送完整列表）。

驗收：
1. 非發布日找不到摘要：不重試、不呼叫 `claude -p`，exit 0。
2. 發布日第一次找不到、第二次找到：中間等 30 秒，之後照常改寫，exit 0。
3. 發布日一直找不到：重試到 05:58 為止，印錯誤，exit 1，不呼叫 `claude -p`。
4. `NEWS_PUBLISH_WEEKDAY` 留空：每天都當發布日（找不到會重試、最後 exit 1）。
5. 找到筆記時已經 05:57:00：`claude -p` 的逾時是 150 秒（到 05:59:30）。
6. 找到筆記時已經 05:58:40（距 05:59:30 不到 60 秒）：不呼叫 `claude -p`，exit 1。

## 2. 去重比對的標題清單去掉重複

目前：`news_digest.py` 的 `seen_titles` 把「摘要筆記的標題」「發布紀錄」「暫存」直接串起來，同一則新聞會重複出現，週報時可達 1500～2000 個，每則新新聞都要全部比一次相似度，拖慢 05:50 的 Job。

期望：交給 `collect()` 的 `seen_titles` 不含重複（保留原本順序）；`seen_keys` 本來就是 set。

驗收：
7. 摘要筆記和發布紀錄有同一個正規化標題時，`collect()` 收到的 `seen_titles` 裡只出現一次。

## 3. 模型寫的文字不能帶連結或 HTML

目前：`text` 原樣寫進筆記。新聞標題是外部內容，prompt injection 雖然沒有工具可用，仍可能讓 `text` 夾帶連結、`<img>`、假的 `##` 標題，經 joplin-proxy 出現在 Instapaper。

期望：
- 任一段 `text` 含有 `<`、`>`、`](`、`http://`、`https://`、`www.` 任一個 → 整篇判為失敗（不改筆記，exit 1）。
- 每段 `text` 的換行與連續空白壓成一個空格（就是「一段話」），開頭的 `#` 去掉，避免變成標題。

驗收：
8. `text` 含上面任一字串 → 不改筆記、exit 1、印錯誤。
9. `text` 為 `"## 假標題\n\n第二段"` → 改寫後那段是 `假標題 第二段`，不會出現 `## 假標題` 這一行。

## 6. 解析筆數跟開頭那行不符要警告

目前：網址含 `)` 或空白、標題含 `\` 的新聞解析不到，會悄悄消失。

期望：開頭那行「共 N 則」的 N 跟解析出來的筆數不同時，在 stderr 印警告（寫兩個數字），其他照常。開頭那行沒有「共 N 則」就不比。

驗收：
10. 內文有一則解析不到 → stderr 有警告、含兩個數字，改寫照常進行。
11. 筆數相同 → 不印警告。

## 7. INBOX 找不到時不建立筆記本

目前：`digest_summary.py` 用 `note2read.get_notebook_id_by_name`，找不到名稱時會**建立**新筆記本，之後永遠找不到摘要，且 exit 0。

期望：`digest_summary.py` 自己查筆記本（`GET /folders`，完全比對標題），找不到就印錯誤、exit 1，不建立任何東西。

驗收：
12. `INBOX` 對應的筆記本不存在 → exit 1、印錯誤、沒有任何 POST 請求。
