# T44：新使用者段落的起點改用上次統計檔的 generated

接 T42（`docs/specs/T42-new-users-section.md`）。

## 目前行為

「新使用者」段落只放 `firstSeen` 晚於「上一篇摘要筆記建立時間」的項目。統計檔是 05:30 產生的，摘要在 05:50 發布，所以 `firstSeen` 落在前一天 05:30–05:50 之間的項目會被漏掉：

- 前一天的統計檔 05:30 就產生了，裡面還沒有這些項目；
- 今天又因為它們早於前一篇摘要（05:50）而被排除。

這個缺口每天約 20 分鐘，改成每週發布後也一樣存在。

## 期望行為

起點改成「上次成功發布時用到的統計檔 `generated` 時間」。這個時間（以下稱游標）記在暫存目錄裡。統計檔只會包含 `generated` 之前出現的項目，所以從游標往後算，不會漏也不會重複。

- 游標檔：`NEWS_NEW_USERS_CURSOR`，預設跟 `NEWS_STATE_FILE` 放在同一個目錄，檔名 `new_users_cursor.json`。正式環境放在 PVC `/state/new_users_cursor.json`，不用改 K8s 設定。
- 內容：`{"generated": "<ISO 8601，原樣抄統計檔的 generated>"}`。

## 驗收條件

1. 游標檔存在且合法時，以游標當起點：`firstSeen` 嚴格晚於游標才算新的，不再查上一篇摘要筆記的時間。
2. 游標檔不存在時，退回目前的做法（上一篇摘要筆記的建立時間；沒有摘要就全收）。部署後第一次發布就走這條路。
3. 游標檔壞掉（不是 JSON、缺 `generated`、時間無法解析）時，同第 2 條，並在 stderr 印一行警告。
4. 筆記建立成功、而且這次有讀到合法統計檔（`load_new_users` 有回傳資料）時，把該檔的 `generated` 寫進游標檔。即使這次篩出來的新使用者是 0 個也要寫。寫法跟暫存檔一樣：先寫 `.tmp` 再 rename。
5. 以下情況**不更新**游標：
   - `--dry-run`；
   - `--collect`／累積模式；
   - 統計檔不存在、過期或格式不對（這一段沒放）；
   - 功能關閉（沒設 `NEWS_NEW_USERS_FILE`）；
   - 沒有建立筆記（沒有新聞也沒有新使用者）；
   - 建立筆記失敗。
6. 同一天重跑發布（同一個統計檔）：游標等於檔案的 `generated`，所以新使用者是 0 個，不會重複列出。
7. 驗收例子：游標 = 前一天 05:30，前一天 05:40 出現的裝置會出現在今天的摘要裡（目前的版本會漏掉它）。

## 不做

- 不改統計檔格式，也不改 garmin 那邊。
- 不改輸出格式和隱私規則（沿用 T42）。

## 限制

- 相容性：功能關閉時，行為和輸出跟目前完全一樣，也不會讀寫游標檔。
- 游標檔只放一個時間，不含任何使用者資料。

## 測試

用 pytest 驗證第 1–7 條。測試不連網路、不連 Joplin，游標檔放在 `tmp_path`。

## 部署

- build `joplin2readeck:1.4.1`（同時更新 `latest`）。
- CronJob 和 ConfigMap 都不用改。
- 部署後第一次發布會走第 2 條（從上一篇摘要開始算），之後就改用游標。

## 回滾

把 image 換回 `1.4.0`。游標檔留著也沒關係，舊版不會讀它。
