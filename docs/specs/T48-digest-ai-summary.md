# T48：新聞摘要改成「影響全世界／全台灣／少數人」三段話

## 背景

每天的新聞摘要動輒 80～200 則，太多看不完。使用者想要依影響範圍分成三類，每類讀一段話就好。

分類和寫摘要需要語言模型。使用者不接受另外申請 API key 和付費，所以改用主機上的 `claude -p`（Claude Code 非互動模式，走使用者現有的 Claude 訂閱）。`claude -p` 只能在主機上跑，所以這一步放在主機 cron，不放在 K8s。

2026-11-21 試跑：86 則標題，`claude -p` 花 26 秒產出三段，品質可用。

## 範圍

做：
- 新程式 `digest_summary.py`（joplin2kobo repo），由主機 crontab 每天 05:52 執行。
- 找出今天 05:50 建立、還在收件匣裡的摘要筆記，交給 `claude -p` 分三類各寫一段，再把筆記改寫成「三段話＋相關連結」。
- `news_digest.py` 發布時，把這次發布的所有新聞記到 PVC 的發布紀錄，讓跨日去重不依賴筆記內容（因為改寫後的筆記不再列出全部新聞，見「去重」）。

不做：
- 不改新聞來源、抓取、05:50 發布時間。
- 不改「新使用者」段落（T42／T44），改寫時原樣保留。
- 不接 Claude API。

## 流程（`digest_summary.py`）

1. 用 Joplin Data API 找收件匣（`INBOX`）裡標題以 `NEWS_TITLE_PREFIX` 開頭、建立時間是今天（台北時間）的筆記。沒有就結束（exit 0，例如週報模式不是發布日）。
2. 筆記內文已經有改寫標記 `<!-- ai-summary -->` 就結束，不重做。
3. 解析內文：開頭那行、「新使用者」段落（如果有）、所有新聞項目（標題、網址、來源與時間那行、簡介）。
4. 把新聞編號（1…N）連同分類、標題、簡介交給 `claude -p`，要求只輸出 JSON：
   ```json
   {"world":  {"text": "…", "refs": [1, 5, 9]},
    "taiwan": {"text": "…", "refs": [2, 3]},
    "local":  {"text": "…", "refs": [7]}}
   ```
   `text` 是繁體中文一段話、約 300 字、只根據提供的標題和簡介；`refs` 是這段話提到的新聞編號。
5. 檢查輸出（見驗收條件），合格才改寫。
6. 改寫前再讀一次筆記：如果已經不在收件匣（06:00 的 note2read 已經把它送出並搬走），就不改，記一筆 log 結束。
7. 用 `PUT /notes/{id}` 寫回新內文。

### 改寫後的內文

```
<開頭那行，原樣>

<## 新使用者 段落，原樣；沒有就省略>

## 影響全世界

<一段話>

- [標題](網址)  
  中央社 · 11/21 08:30
- …

## 影響全台灣
…

## 影響少數人
…

<!-- ai-summary -->
```

- 每段底下只列 `refs` 指到的新聞，依編號順序，格式與原本列表相同但不放簡介。
- 網址一律取自原筆記，不用模型輸出的任何網址。
- 某一類的 `text` 是空字串（例如那天沒有「影響全世界」的新聞）：整個小節省略。

### 呼叫 `claude -p`

- 關掉所有工具與自訂設定，只讓它輸出文字：`claude -p --tools "" --safe-mode --strict-mcp-config --no-session-persistence --output-format json`，prompt 從 stdin 傳入。新聞標題和簡介是外部內容，不能讓它有能力執行任何動作。
- 逾時 240 秒（05:52 開始，06:00 之前要結束）。

## 去重

`news_digest.py` 目前靠讀最近的摘要筆記裡的連結做跨日去重。改寫後筆記只留部分連結，其他新聞隔天可能又被收進來。

改法：發布成功後，把這次發布的每則新聞（網址 key、正規化標題、日期）附加到 `NEWS_PUBLISHED_FILE`（預設與 `NEWS_STATE_FILE` 同目錄的 `news_published.json`），只保留 `NEWS_DEDUP_DAYS` 天內的。去重時，筆記裡的連結和這個發布紀錄取聯集。

## 驗收條件

`digest_summary.py`：
1. 收件匣裡沒有今天的摘要筆記 → 不呼叫 `claude -p`、不改任何筆記，exit 0。
2. 筆記已有 `<!-- ai-summary -->` → 不呼叫 `claude -p`、不改，exit 0。
3. 解析：從 `render()` 產生的內文能取回每則新聞的標題（含跳脫的 `[`、`]`）、網址、來源時間行；「新使用者」段落和開頭那行原樣取回。
4. 交給 `claude -p` 的 prompt 包含每則新聞的編號、分類、標題、簡介，不包含網址。
5. 輸出合格時，改寫後的內文符合上面的格式：開頭那行、新使用者段落（如果有）、三個小節（空的省略）、每節列出 refs 指到的新聞、結尾標記。
6. `refs` 裡超出範圍、重複或不是整數的編號忽略；某節 `text` 不是空的但所有 refs 都無效，該節照樣放那段話，底下不列連結。
7. 以下都**不改筆記**、印錯誤訊息、exit 非 0（cron log 看得到）：`claude -p` 逾時、結束碼非 0、輸出不是 JSON、缺 `world`／`taiwan`／`local` 任一鍵、`text` 不是字串、三段 `text` 全是空的。
8. 改寫前筆記已不在收件匣 → 不改，exit 0 並印一行說明。
9. 呼叫 `claude -p` 的參數包含 `--tools ""`、`--safe-mode`、`--strict-mcp-config`、`--no-session-persistence`。

`news_digest.py`：
10. 發布成功後，發布紀錄包含這次的每則新聞；超過 `NEWS_DEDUP_DAYS` 天的紀錄被清掉；寫法是先寫 `.tmp` 再 rename。
11. `--dry-run`、累積模式、沒有建立筆記、建立筆記失敗，都不寫發布紀錄。
12. 去重時，發布紀錄裡的網址或相似標題跟筆記裡的一樣會被排除。發布紀錄不存在或壞掉時，只用筆記（壞掉時印警告）。

## 部署

- 主機 crontab（使用者 dany）：`52 5 * * * cd ~/projs/joplin/joplin2kobo && uv run python digest_summary.py >> ~/.local/state/news-summary/summary.log 2>&1`。
- 環境變數放 `~/.config/news-summary.env`（不進 repo）：`JOPLIN_DATA_API_URL`、`JOPLIN_DATA_API_TOKEN`、`INBOX=kobo`。
- K8s：image 升 `1.5.0`（發布紀錄）；CronJob／ConfigMap 不用改。

## 限制

- 時間：`claude -p` 必須在 06:00 note2read 之前完成。來不及就照舊送原本的完整摘要（驗收條件 8）。
- 用量：每天一次 `claude -p`，佔用使用者的 Claude 訂閱額度。
- 改成每週（T43）後，一次可能有 300 則以上，prompt 會變長，屆時再看時間是否足夠。
- 正確性：摘要由模型產生，可能有誤；只根據標題和簡介，不讀全文。
